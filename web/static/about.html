About the model

Food–Drug ML model with SHAP — a three-class interaction predictor built from the FHDI gold-standard dataset, molecular descriptors, grouped-drug validation, explainability, and a safety-first inference layer.

Abstract

The system predicts the effect of pairing a drug with a food compound in one of three classes: avoid together, beneficial / take with food, or non-significant. Each molecule is represented by 60 MOE descriptors from RDKit/PyBioMed. Drug–compound pairs are expanded into 3,780 pairwise features (descriptor products, sums, absolute differences and ratios), then reduced to 18 features by variance, correlation, LASSO and permutation selection. Five classifiers are tuned on a validation partition: XGBoost, LightGBM, RandomForest, ExtraTrees and a multi-layer perceptron. Models are evaluated with a drug-grouped split (Split G) for honest generalization to unseen drugs, plus a random split (Split R) for paper comparability. The deployed LightGBM model is wrapped in a rule/evidence inference layer, abstains below a 0.6 confidence threshold, and is explained with SHAP.

How a prediction is made

  1. Input resolution. Drug and food names, IDs or SMILES are normalized and matched against curated tables. Food names are expanded to marker compounds (for example grapefruit → naringin/bergamottin).
  2. Clinical rule layer. Well-established interactions (warfarin + grapefruit, simvastatin + grapefruit, metronidazole + alcohol, tetracyclines + calcium, MAO inhibitors + tyramine) short-circuit to a conservative verdict with a stated reason.
  3. Exact-pair dataset evidence. If the labelled dataset contains a non-synthetic annotation for the exact drug–compound pair, that label is used and shown as evidence.
  4. ML scoring. Otherwise the pair is featurized and the trained LightGBM model returns three class probabilities. The UI displays the winning class, the probability bars, applicability-domain similarity and latency.
  5. Abstention. If the top probability is below 0.6, or the drug is outside the applicability domain, or the compound is inorganic, the system refuses to give a confident verdict and asks the user to consult a pharmacist.

Architecture

Backend — FastAPI

  • Lazy, thread-safe engines per label mode (S/P), loading the frozen models once.
  • POST /api/predict — verdict, probabilities, sentence, matched compounds, latency.
  • GET /api/suggest — autocomplete over 1,359 drugs and 4,877 compounds.
  • GET /api/health, GET /api/examples — readiness and demo pairs.
  • GET /, /predict, /about — landing, predictor, documentation pages.

Frontend — vanilla HTML/CSS/JS

  • Landing page, predictor page and this about page; no framework or build step.
  • Fetch API with debounced autocomplete and AbortController for stale requests.
  • XSS-safe DOM rendering via textContent; accessible labels and ARIA states.
  • Probability bars, evidence/rule badges, confidence, domain similarity and candidate compounds.

Techniques used

Molecular representation

RDKit parses and canonicalizes SMILES. PyBioMed computes 60 MOE descriptors per molecule; inorganic or metal-containing compounds are refused.

Pairwise feature algebra

For 60 descriptors: 3,600 products, 60 sums, 60 absolute differences and 60 ratios, giving 3,780 candidate features that encode both molecules and their complementarity.

Tanimoto / Morgan fingerprints

Nearest-neighbour Tanimoto similarity on 2,048-bit Morgan fingerprints powers the applicability domain. It is also used during cleaning to remove near-duplicate compounds.

Feature selection

Variance filter, Pearson correlation pruning (0.75), LASSO, stability selection and permutation importance reduce 3,780 features to 18.

Models & tuning

XGBoost, LightGBM, RandomForest, ExtraTrees and MLP, tuned with RandomizedSearchCV on a validation partition. Balanced class weights and 0.5 weights for weak synthetic pairs address the severe imbalance.

Grouped validation

Split G holds out whole drugs to measure generalization to unseen drugs. Split R is a random split for paper-style comparison. GroupKFold is used inside training.

SHAP explanations

TreeSHAP explains each class on the test partition, producing global summary plots and per-class feature attributions. The same feature set is consumed by the deployed model.

Calibration & abstention

Split-conformal calibration targets 90% coverage; a confidence-threshold sweep selects the 0.6 operating point. Low-confidence and out-of-domain inputs abstain instead of guessing.

Two label modes

Specific (Mode S) — default

Labels only the compounds named by the interaction text, curated marker compounds of a named food, or food-specific compounds. Corrected semantics treat warning-style “Positive” annotations as avoid. 444 labelled drugs, 21,042 pairs.

Paper-like (Mode P)

Reproduces the source paper: one drug-level label applied to every sampled food compound. Large coverage (1,359 drugs, 407,699 pairs) but leakage-prone, so its random-split scores are optimistic. Kept for comparability.

Limitations & safety

  • Descriptor-only features cannot identify a named drug, so known clinical pairs rely on the rule and evidence layers. The ML model handles unseen, chemically plausible pairs.
  • Class 0 recall on unseen drugs is about 0.32 at the default threshold; abstention is preferred over confident errors.
  • Mode S covers 444 labelled drugs. Pairs outside that coverage are extrapolation and are labelled as such.
  • This is a research tool. It does not replace clinical judgement; always confirm with a physician or pharmacist.
